# PROJECT_MEMORY.md

This file is persistent project memory for AI agents.

## Project Identity

Name: Smart Grocery Store Management System

Type: College field project.

Core purpose: automate grocery store operations through a web application.

## Approved Core Modules

- Inventory Management
- POS / Billing
- Sales Tracking
- Customer Management
- Dashboard
- Reporting

## Current Stack

Frontend:
- HTML

- JavaScript

Backend:
- Python
- Flask

Database:
- MySQL

Development:
- Google Antigravity
- Git
- GitHub

## Current Stage

Stage: Planning / initial implementation.

Do not assume features are complete unless TASKS.md or test evidence says so.

## Product Principles

1. Keep the application simple and demonstrable.
2. Prefer reliable features over large feature count.
3. Build the MVP before future enhancements.
4. Keep business logic on the backend.
5. Validate all important input.
6. Make the UI understandable.
7. Every major workflow must be testable.

## Future Enhancements

The original project includes:

- AI-based product suggestions
- Mobile self-scanning
- Smart demand forecasting

These are not MVP requirements.

## Important Assumptions

- Local development is sufficient for the first version.
- Online payment is not required for MVP.
- Real barcode hardware is not required for MVP.
- Multi-location support is future scope.
- Customer functionality can initially be represented through customer records and purchase history.

## Agent Memory Rules

When a significant project decision changes:

1. Update this file.
2. Add the reason to DECISIONS.md.
3. Update PRD/ARCHITECTURE if the decision changes requirements.
4. Update TASKS.md.

Do not store secrets, passwords, API keys, or private credentials here.

## Current Known Risks

- Beginner may accept generated code without understanding it.
- AI-generated code may contain incorrect assumptions.
- Database changes can break existing features.
- Large prompts can cause agents to modify too much at once.

## Mitigation

Work in small milestones, test after each milestone, and require agents to explain changes.
